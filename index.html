AI news for Data Products and Data Platforms

  1. 01
    US bank regulator sets out how examiners will judge AI agents

    The OCC issued a non-binding, 22-page supervisory framework on 4 November, with Bulletin 2026-54, telling examiners to assess generative and agentic AI through existing risk categories across six pillars (purpose, risk, control, oversight, resilience and assurance), weighing how much autonomy a system holds and whether its actions can be reversed, and pointing to circuit breakers, rate limits and restricted permissions as safeguards. FinTech Futures · 2026-11-04

    Examiners now have a written checklist that asks how much authority an agent holds over data and how it is stopped, so a platform roadmap enabling agentic access should be able to show per-agent permissions, rate limits and a kill switch on governed datasets as evidence, not as a design intention.

  2. 02
    Thoughtworks Radar moves the Open Data Contract Standard to Adopt

    Volume 35 of the Technology Radar, published on 4 November, places the Open Data Contract Standard in its Adopt ring and calls it a sensible default for teams building data products, because the declarative YAML format is easier for both people and AI agents to read, review and validate; the maintainers of Data Contract CLI have deprecated their own format in favour of it. Thoughtworks Technology Radar, Vol. 35 · 2026-11-04

    A consultancy that advises many enterprise data teams now recommends one contract format by default, which narrows the buy-versus-build question for contracts: a catalog, quality or observability tool that cannot read and write ODCS is now the one that has to justify itself.

  3. 03
    Half of security leaders report data exposed through AI tools

    A Sapio Research survey of 400 security decision-makers at UK and US companies with more than 500 staff, commissioned by BlackFog and published on 3 November, found 47% had seen sensitive data exposed through an AI tool, and in 77% of those cases a sanctioned, company-approved tool was involved; only 27% of those who said adoption was outpacing governance had comprehensive controls. Infosecurity Magazine, on BlackFog research · 2026-11-03

    The exposure is coming mostly through approved tools, not shadow AI, which makes the controls on a governed dataset (masking, scoped access, logging of what an AI tool read) the part of the platform that carries the risk, rather than the tool allow-list.

  4. 04
    DataKitchen ships ODCS data contracts in open-source TestGen

    DataKitchen said on 13 November that data contracts now ship in its Apache 2.0 TestGen tool, which writes an ODCS contract from tables it has already profiled and attaches a test to each quality rule, so a supplier can run the contract before sending data and a recipient can reject files that fail. DataKitchen · 2026-11-13

    For a platform that receives data from external partners, a free tool that turns profiling into an enforceable contract both sides can run is a cheap way to move quality checks to the supplier, and a useful benchmark for what a paid contracts feature has to add.

AI-ready vs analytical-ready data

  1. 01
    Snowflake's AI_EXTRACT reads dense tables, charts and handwriting

    Snowflake's 2 November release note puts an update to AI_EXTRACT into public preview that extracts fields, lists and tables more accurately from complex documents, including forms, handwritten content, dense tables and charts; the older Document AI workflow is being retired in favour of the function. Snowflake release notes · 2026-11-02

    Document extraction is becoming a SQL function on the governed platform rather than a separate pipeline, so the open question for a roadmap is less the extraction itself than whether extracted fields land with the same lineage, ownership and quality checks as the tables beside them.

  2. 02
    Pin agent SQL evaluations to a data snapshot

    An evaluation guide from Braintrust argues that text-to-SQL agents should be scored on whether a query runs separately from whether its result is correct, with every comparison pinned to a fixed database snapshot and reference-dataset version, reference queries rerun after each data or schema refresh, and changed results reviewed before expected answers are updated. Braintrust · 2026-10-18

    Without a pinned snapshot a routine refresh of a gold table can make a correct agent look wrong, or a wrong one look right, so a platform validating conversational access needs versioned evaluation datasets as a governed asset alongside the tables the agent queries.

So You Want to Work With Data Contracts and Data Products?

A data contract is a written promise from whoever produces a dataset to whoever uses it: what columns it has, what the values mean, how fresh it will be and what quality checks it passes. A data product is the dataset plus that promise plus an owner who answers for it. The Open Data Contract Standard (ODCS) writes the promise in a fixed, machine-readable format, and the companion Open Data Product Standard (ODPS) describes the product around it, so tools and agents can check the promise rather than trusting it. This series walks through writing a first ODCS contract and then assembling a data product from it.

For the roadmap With ODCS now a default recommendation, the practical decision is where contracts are authored and enforced on the platform: in the transformation layer, in the catalog, or at the point a partner sends data. Working through a first contract by hand shows which of those fields a gold-layer dataset already has and which nobody owns yet.
