AI news for Enterprise Data Platform Product Management

  1. 01
    Snowflake native apps can now ship their own MCP servers

    As of August 7, a Snowflake Native App can create Cortex Agents and Snowflake-managed MCP servers directly, exposing its shared data and functionality as MCP tools to agents inside or outside Snowflake. Snowflake Documentation · 2026-08-07

    Vendors can now ship an MCP surface as part of the app itself, so evaluating Snowflake-native tooling no longer means budgeting a separate integration layer just to make it agent-reachable.

  2. 02
    Critical flaws let attackers hijack AI agent control planes

    Oasis Security disclosed three flaws in Paperclip, an open-source control plane for orchestrating autonomous AI agents — including an unauthenticated bug (CVSS 10.0) that let an attacker self-register and obtain persistent admin-level API access — now patched in 2026.416.0. The Hacker News · 2026-08-05

    Any team standing up agent orchestration on top of its data platform now has a concrete case for treating that control plane with the same access-review rigor as the warehouse it drives.

  3. 03
    Databricks makes Delta sharing with deletion vectors GA

    From August 4, Databricks generally supports sharing Delta tables that have deletion vectors or column mapping enabled, removing a prior blocker to exchanging modern Delta tables through Delta Sharing. Databricks Release Notes · 2026-08-04

    Teams sharing Delta tables across business units or with partners no longer have to strip out performance features to make a table shareable — one less table-format compromise on the lakehouse roadmap.

  4. 04
    Snowflake adds an agent-activity column to its access-history view

    Since August 3, the ACCESS_HISTORY view carries a new agents_info column recording which AI agents accessed data on a user's behalf, across both account- and organization-usage views. Snowflake Documentation · 2026-08-03

    It's a small feature with an outsized governance payoff: audit and data-quality teams get a native way to see which queries against a table were agent-initiated rather than human, instead of inferring it after the fact.

AI-ready vs analytical-ready data

video · AtScale — expert panel (on-demand video)
Building the Intelligent Data Layer: Governance, Semantics, AI Readiness

Picture a company's data as a huge library where every department labels its own shelves differently. A semantic layer is a librarian who translates all those labels into one shared catalogue, so when someone — or an AI model — asks for "revenue," everyone gets the same number, calculated the same way, instead of five different answers from five different spreadsheets. Governance is the library's rulebook layered on top: who's allowed to see which shelf, and a record of who looked. Put the two together and the data isn't just organized — it's trustworthy enough to hand to a model that will act on the answer without a human checking it first.

For the roadmap The panel's core argument — that governance and semantics have to be built together, not bolted on after the AI features ship — is the case for funding the semantic layer as infrastructure on this year's roadmap rather than revisiting it as a BI nice-to-have once agents are already in production.
