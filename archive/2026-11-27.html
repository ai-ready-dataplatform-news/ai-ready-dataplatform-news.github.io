AI news for Data Products and Data Platforms

  1. 01
    MongoDB buys Firebolt to put analytics beside operational data

    MongoDB announced on 17 November that it has acquired Firebolt, the Israeli low-latency analytics engine that had raised about $270 million. The plan is to run Firebolt alongside MongoDB's operational database and keep the two in sync automatically, so serving analytics to applications and agents no longer needs a separate pipeline. Price was not disclosed, reported as well below Firebolt's earlier $1.4 billion valuation, and the integration is still months from customers. MongoDB blog, with the SEC 8-K filing · 2026-11-17

    Any shortlist that includes Firebolt for high-concurrency serving now carries vendor risk and an owner with different priorities. Operational databases are also absorbing analytics engines, so the case for copying application data into the lakehouse just to serve agents needs restating with numbers.

  2. 02
    LanceDB raises $57.5M for a multimodal lakehouse

    LanceDB closed a $57.5 million Series B on 17 November, led by Bessemer and Innovation Endeavors, which brings its total funding to $98.5 million. It builds a multimodal lakehouse on its open-source Lance format for images, video and other AI training data. Revenue has reportedly grown more than tenfold since its June 2025 Series A, and Runway is a named customer. Bessemer Venture Partners announcement · 2026-11-17

    Lance now has the funding to compete with Iceberg and Delta for multimodal data. The table-format decision for document, image and video data deserves its own look rather than a default to whatever the tabular estate uses.

  3. 03
    Market data vendor Databento reaches a $1.1B valuation

    Databento raised a $100 million Series C at a $1.1 billion valuation, led by Fifth Down Capital with Fitch Ventures joining as a strategic investor. The round came four months after a $97 million Series B. The company says revenue has more than doubled since then while it stayed profitable, with 39 staff. The money goes to more exchange coverage, faster delivery and larger institutional customers. Databento blog · 2026-11-13

    API-first, usage-priced market data is pulling serious money as a challenger to terminal-style licensing. When a market-data contract comes up for renewal, a consumption-priced feed delivered straight into the platform is now a credible option to price against.

AI-ready vs analytical-ready data

  1. 01
    Databricks checks embedding inputs for sensitive data

    A Beta dated 18 November extends Unity Gateway service policies to single and batch embedding requests, so sensitive data or unsafe content can be caught before the model runs. The scope is narrow: only the input is checked, nothing evaluates the resulting vectors, and a denial rejects the whole request with an HTTP 400. Databricks Unity Gateway release notes · 2026-11-18

    This puts a governance check at the point where text becomes vectors, which is where PII usually escapes into a vector index unseen. A RAG roadmap can now plan on a gateway-level policy at ingestion, but bad batch requests are blocked rather than masked, so indexing pipelines need to handle failures.

  2. 02
    SnapLogic ships a governed registry of MCP servers

    SnapLogic's Discovery Hub, launched on 17 November, gives teams one catalog for finding and reusing MCP servers and tools. Together with access policies and usage monitoring, SnapLogic calls it the environment's MCP gateway. Only SnapLogic-native servers are generally available, and third-party MCP discovery and agent observability are still on the roadmap. Unite.AI, on SnapLogic's Discovery Hub launch · 2026-11-17

    Integration platforms are now competing to be where agent-facing data interfaces are registered and governed. Deciding who owns the catalog of MCP surfaces (data platform, integration layer or agent platform) belongs on this quarter's roadmap before three teams each build one.

  3. 03
    Query logs as the missing documentation for text-to-SQL

    A preprint by Akgül, Kapahi and Muppidi argues that enterprise text-to-SQL fails mostly because schemas are undocumented, with cryptic names and implicit relationships. It builds a knowledge graph offline from historical query logs: which tables are queried together, how they join, and which columns map to business concepts. The authors also note that many enterprise questions have several valid SQL answers, so scoring against one gold query understates accuracy. arXiv preprint, University of Southern California and Amazon authors · 2026-10-24

    Query history is an AI-readiness asset the platform already owns, and it can draft context for agents where catalogs are empty. Retention and access to query logs belong in the agent-context plan, and evaluation suites should accept several valid answers before a vendor's accuracy number is believed.

Building and Evaluating Data Agents

A data agent takes a question in plain words, decides where to look, runs queries or searches, and writes an answer. It can go wrong at any of those steps: it can pick the wrong table, fetch context that does not answer the question, skip a step in its own plan, or state something the data does not support. Evaluating it properly means checking each step, not only whether the final answer looked right, so a failure can be traced to where it started. This roughly two-hour intermediate course builds an agent and then evaluates it, in eight video lessons with code.

For the roadmap Step-level evaluation is what turns an agent pilot into something a platform team can support. A data-agent launch should be gated on an evaluation suite that scores retrieval relevance and groundedness as well as answer correctness, owned by the platform team alongside the semantic model it relies on.
