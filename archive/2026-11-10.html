AI news for Data Products and Data Platforms

  1. 01
    AWS will migrate Hive tables to managed Iceberg for you

    Amazon S3 Tables now runs a managed migration of Glue-registered Hive tables stored as Parquet into managed Iceberg tables, handling compatibility checks, type conversion and compaction, leaving the source table untouched and the target read-only until the job completes, and charging only for the data copied. AWS News Blog · 2026-11-04

    A migration that writes a compatibility report before copying anything and leaves the source intact as a fallback lowers the cost of moving legacy lake tables, which is the line item that usually sinks a format migration in a buy-versus-build or cost-per-dataset case.

  2. 02
    Chord buys Zenlytic to make AI reliable on company data

    Chord, a commerce data platform, announced on 3 November that it has acquired AI business-intelligence startup Zenlytic in an all-stock deal reported at about $5 million; the company says it doubles Chord's revenue and adds customers including Verizon, J.Crew and Domino's, and Zenlytic's analyst agent Zoë is reported to replace Chord's own. Runtime Wire · 2026-11-03

    AI analyst tools built on a customer's own warehouse are consolidating cheaply, so anyone buying one for governed, conversational access should get warehouse support, pricing and continuity terms in writing, since none were announced for existing Zenlytic customers.

  3. 03
    Nine million synthetic financial customers released for open use

    Elith and NVIDIA released Nemotron-Personas-Finance-Japan on 9 November, nine million synthetic Japanese personas licensed for commercial and non-commercial use, built for testing customer-facing financial systems without real customer records. Unite.AI · 2026-11-09

    A free, licensed synthetic customer population is a data product aimed squarely at regulated testing, and it gives a financial-services platform team a reference point when weighing whether to build synthetic test data for its own market or wait for someone to publish it.

  4. 04
    Databricks Lakebase Postgres now runs on all three clouds

    Databricks made Lakebase, its serverless Postgres database that runs on the Databricks platform, generally available on Google Cloud on 2 November in five regions, completing general availability after AWS earlier in 2026 and Azure in April. Let's Data Science · 2026-11-02

    With an operational database available inside the lakehouse on every major cloud, serving an application from the same governed data stops being a cloud-specific exception, and the question of whether serving tables belong in the platform or in a separate app database becomes a roadmap decision rather than a constraint.

  5. 05
    Snowflake can now back up and restore its Iceberg tables

    Backups for Iceberg tables held in Snowflake Storage, including dynamic Iceberg tables, reached general availability on AWS on 4 November, with backup sets, restore commands and inclusion in schema and database backups. Snowflake release notes · 2026-11-04

    Open-format tables were missing the backup and restore controls teams expect of warehouse tables; closing that gap matters to an operational-resilience review, where recovery of the gold layer has to be shown rather than assumed.

AI-ready vs analytical-ready data

  1. 01
    Bloomberg opens its licensed data to AI agents

    Bloomberg launched Enterprise MCP on 20 October, an access layer over its Data License Plus product that lets AI agents use licensed reference and pricing data covering more than 100 million securities and over 50,000 fields. CFOtech · 2026-10-20

    When a major data vendor ships an agent interface over the licence a firm already holds, the agent-facing contract is defined by the supplier; a platform team has to decide whether agents reach vendor data through that interface or through the governed copy in its own gold layer, and keep the two consistent.

  2. 02
    AWS lets agents query the lake as the signed-in user

    An AWS Security Blog pattern carries each user's identity through the agent and into the tool, exchanging it server-side for Lake Formation credentials scoped to that user, so existing row and column grants apply unchanged and CloudTrail records every query against the real person rather than the agent's role. AWS Security Blog · 2026-10-06

    Making the user, not the agent, the subject of every access check is how one governed dataset can serve dashboards and agents under the same policy, which is the condition for analytical and agentic consumption not diverging.

  3. 03
    A single MCP gateway between agents and the data lake

    An AWS reference design puts one agent-agnostic MCP server in front of the data lake, with Athena for SQL and Bedrock Knowledge Bases for search over documentation, read-only enforcement at the tool, and new datasets onboarded by writing a metadata file rather than code; it reports 15 to 20 seconds from question to answer. AWS Machine Learning Blog · 2026-11-06

    Onboarding a dataset for agents by metadata file rather than code is the agent-side equivalent of cutting time-to-onboard, and enforcing guardrails once at the gateway rather than per agent is the design choice to test against any vendor's managed MCP offer.

  4. 04
    Snowflake's catalog now governs tables other catalogs own

    Since 29 October, external engines such as Spark, Trino, DuckDB and PyIceberg can read and write externally managed Iceberg tables through Snowflake Horizon Catalog's Iceberg REST API, with Snowflake role-based access governing them, provided the remote catalog implements the matching REST operation. Snowflake release notes · 2026-10-29

    Catalogs are competing to be the one place policy is enforced over tables they do not own, which turns the catalog decision into a question of whose access model applies when two engines touch the same table.

  5. 05
    Snowflake's MCP server lets agents run long jobs

    From 4 November the Snowflake-managed MCP server accepts an optional background flag on its agent and coding-agent tools, returning a handle immediately that the client polls for the result, alongside additional supplementary tools for agents. Snowflake release notes · 2026-11-04

    Agents that hand off long analytical work and come back later need the same lineage and audit trail as a scheduled job, so the asynchronous path is where a governance review of agent access should look first.

case study · Monte Carlo
How Roche built trust in the data mesh with data observability

Roche let each business area own and publish its own data, as products other teams could pick up, instead of routing everything through one central team. It grew to around 30 domains and at least 300 data products, found through a self-serve marketplace. The catch was trust: with roughly one developer for every hundred tables in production, nobody could check data by hand, so automated monitoring became the thing that told consumers whether a product was safe to use.

For the roadmap It shows where modelling authority can sit with domains only if the platform supplies the trust signal centrally, which bears directly on the central-versus-domain ownership decision and on what a foundation-phase scorecard should measure: monitored coverage per data product, not just how many were published.
