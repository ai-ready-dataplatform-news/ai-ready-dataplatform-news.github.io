AI news for Enterprise Data Platform Product Management

  1. 01
    Apache Iceberg 1.12.0 ships with more server-side catalog policy

    Iceberg 1.12.0 landed on September 30 with more than 800 merged changes, extending engine support for Variant, row lineage, deletion vectors and encrypted metadata, and letting Spark delegate DROP TABLE PURGE to the REST catalog so the catalog rather than the client decides how files are deleted. Dremio · 2026-09-30

    Moves deletion and policy decisions onto the catalog, which a platform PM choosing where governance is enforced can use as a reason to pick the catalog layer first.

  2. 02
    Atlan stores its context layer as Iceberg tables in OneLake

    Announced at FabCon Europe on September 29, Atlan's Context Lakehouse keeps metric definitions, ownership, lineage, quality and policy, plus observations written back by agents, as open Iceberg tables the customer owns in OneLake, readable by Fabric users and agents without copies. Business Wire · 2026-09-29

    Puts governed context in the customer's own storage rather than a vendor's, which a platform PM weighing catalog buy-versus-build can use to test how portable the metadata really is.

  3. 03
    Bloomberg opens an MCP layer on its data licence

    Bloomberg Enterprise MCP, launched September 29, lets clients' agents discover and retrieve licensed data across more than 100 million securities and 50,000 fields, paired with metadata, semantic context and prebuilt skills such as sanctions-exposure checks. PR Newswire · 2026-09-29

    A financial-data vendor now ships semantics and skills with the feed, so a platform PM planning agent access to licensed data has a vendor-side contract to design against.

  4. 04
    OneLake gets a table read API for agents

    At FabCon Europe, Microsoft put the OneLake Table Read API into preview, giving agents and applications serverless access to Delta and Iceberg tables without SQL, and added Iceberg catalog federation for AWS Glue and Google's lakehouse runtime catalog. Microsoft Fabric Blog · 2026-09-29

    Gives a platform PM a vendor-neutral read path for agents across Delta and Iceberg, which bears on how many serving surfaces the governed layer needs.

AI-ready vs analytical-ready data

  1. 01
    Looker's semantic layer becomes an agent inside Gemini Enterprise

    Looker analysts can publish conversational agents into Gemini Enterprise over the Agent-to-Agent protocol, so a question about revenue is routed to Looker and answered with SQL generated from version-controlled business logic rather than inferred by the model. Google Cloud Blog · 2026-09-14

    Offers a worked route for one set of metric definitions to serve both dashboards and agents, the divergence risk a governed gold layer has to design out.

  2. 02
    Power BI adds an authoring MCP and agentic model building

    The September feature summary makes Power BI agentic experiences generally available for building semantic models and reports, and adds a Power BI Authoring MCP that lets AI applications create and modify semantic models in Fabric workspaces. Power BI Blog · 2026-09-29

    Lets agents edit the semantic model itself, so a platform PM has to decide who reviews a model change that no human wrote.

  3. 03
    ThoughtSpot Spotter Memory goes GA and learns from conversations

    Release 26.9.0 makes Spotter Memory generally available and on by default, generating memory from conversations and Liveboards, and lets one Spotter conversation search several Models at once, such as a revenue and a finance Model. ThoughtSpot Documentation · 2026-09-30

    Lets answers accumulate user-taught definitions outside the governed model, which a platform PM weighing conversational access has to reconcile with the central metric layer.

case study · Netflix Tech Blog
Data Bridge: How Netflix simplifies data movement

Netflix keeps its data in dozens of different stores, and engineers used to learn a dozen different tools just to move data between them. Data Bridge is one front door: an engineer says what they want moved and where, and the platform works out how to do it. The idea is to separate what someone wants from how it is done. That way the tools underneath can change without anyone having to relearn anything.

For the roadmap Frames the decision of whether onboarding a new dataset should be one declarative request to the platform or a bespoke pipeline per team, which is the lever for cutting time-to-onboard.
