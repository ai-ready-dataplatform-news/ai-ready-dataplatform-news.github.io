The state of data mesh in 2026: from hype to hard-won maturity

Data mesh is the idea that instead of one central team owning all of a company's data, the teams closest to each subject — orders, customers, payments — own their own 'data product': a dataset with a name, an owner, a quality bar and a promise about what it means. Thoughtworks' 2026 field report argues the idea has stopped being a slide-deck pitch and become something enterprises actually run, but only where four things are all true together: someone in the domain owns the data, that data is packaged as a product with real consumers, there's a self-serve platform so domains don't need a platform team's help to publish, and a federated set of rules keeps every domain's data usable together rather than each one doing its own thing. The newest twist: those same domain-owned data products increasingly have to work for two different kinds of consumer at once — a person building a dashboard and an AI agent reasoning over the same numbers — which the report calls a 'dual-use' data product, built once and trusted by both.

For the roadmap This is the same question the platform's own foundation-phase roadmap is trying to answer — whether one governed source can serve a dashboard and an agent without the two drifting apart — and it hands over a named pattern, 'dual-use data product', and a maturity bar to borrow rather than invent from scratch.
