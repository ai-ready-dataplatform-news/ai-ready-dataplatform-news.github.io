AI news for Enterprise Data Platform Product Management

  1. 01
    Microsoft to retire Fabric's embedded ODBC drivers

    Microsoft will start pulling Fabric's embedded ODBC drivers for Databricks, Snowflake, BigQuery, Dremio, Impala and Spark connectors from late Q3/Q4 2026, moving connections onto Arrow Database Connectivity instead. Gethyn Ellis · 2026-09-07

    Any Fabric pipeline that leans on the built-in Databricks, Snowflake or BigQuery connector needs an ADBC migration plan before the ODBC path is pulled — worth raising with integration owners now rather than at cutover.

  2. 02
    Valsoft's TAG buys document-AI vendor Square 9

    Valsoft's TAG Software Group acquired intelligent-document-processing vendor Square 9 Softworks, whose software reads invoices, purchase orders and contracts for more than 1,000 organizations across healthcare, government and manufacturing. THE D*AI*LY BRIEF · 2026-09-08

    Another buy-and-hold consolidation of an unstructured-data ingestion vendor — worth checking how sticky the document-AI layer feeding your platform actually is before a roadmap leans on it.

  3. 03
    SANS and AWS: a system prompt isn't a security control

    New SANS and AWS guidance says prompt instructions can be bypassed, ignored or overridden, and recommends enforcing authorization at the data retrieval layer instead, propagating user context through the agent to downstream services. Help Net Security · 2026-09-03

    If agent access to governed data still leans on prompt wording anywhere in the stack, that's the exact gap this guidance calls out — worth an audit before an incident forces one.

  4. 04
    Instacart lets AI agents run its ML experiments

    Instacart has integrated AI agents into its Griffin ML platform to autonomously generate, code and evaluate machine learning hypotheses under human supervision. Data Engineering Weekly · 2026-09-07

    A concrete production example of agentic AI operating inside an ML platform rather than beside it — useful evidence for the build-vs-buy case on agentic tooling in your own stack.

case study · AtScale
Case study: modernizing analytics with a semantic layer

A semantic layer is a single place where a business defines what 'revenue' or 'active customer' actually means, once, so every dashboard, spreadsheet, and now every AI agent that asks for that number gets the same governed answer instead of each tool computing its own slightly different version. This case study follows a large home-improvement retailer that put one in front of its warehouse: hundreds of people who used to build their own Excel pulls now hit the same governed numbers, IT support load dropped, and the company is now layering natural-language question-asking on top of that same foundation.

For the roadmap The retailer's actual win was fewer competing definitions and less manual prep, not a flashy AI feature — a reminder that the unglamorous plumbing work is what determines whether an agent layer built on top ever gives a trustworthy answer.
